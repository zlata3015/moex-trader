# moex-risk — риск-менеджер

```bash
python3 "${CLAUDE_SKILL_DIR}/check.py"
python3 "${CLAUDE_SKILL_DIR}/check.py" --now "2026-11-05 10:20"
python3 "${CLAUDE_SKILL_DIR}/check.py" --status        # сводка рисков портфеля
```

## Правила риска портфеля (настройки по умолчанию)

| правило | настройка | что делает |
| --- | --- | --- |
| риск на сделку 0,5% | max_loss_per_trade | убыток до стопа с издержками |
| дневной лимит 2% | daily_loss_limit | реализованный убыток за день: стоп торговли; сделка не может «добить» лимит |
| недельный лимит 4% | weekly_loss_limit | реализованный убыток с понедельника: стоп до следующей недели |
| открытый риск 3% | max_open_risk | все позиции (включая свинг прошлых дней) до их **текущих** стопов + сегодняшние заявки |
| просадка 7% / 10% | dd_half_pct, dd_stop_pct | от максимума капитала: объём вдвое меньше / пауза и разбор |
| корреляция | corr_threshold 0,7, corr_group_risk_mult 1 | бумаги одной отрасли или с корреляцией ≥ 0,7 считаются одной позицией: их общий риск не больше риска одной сделки |
| эмитент 5% | issuer_limit_pct | корпоративные облигации одного эмитента (ОФЗ не ограничены) |
| прибыль/риск 2 | min_reward_risk | для сделок с целью; стратегия с подтягиваемым стопом проверяется по издержкам |
| бэктест обязателен | require_backtest | сетап без бэктеста или с отрицательным результатом блокируется |

Жёсткие запреты: позиция без стопа (блокирует все новые сделки), усреднение убытка, отодвигание стопа (moex-broker \`set-stop\` и moex-exit \`update\` двигают стоп только в сторону прибыли). Позиция со стопом в безубытке или прибыли не добавляет открытого риска.
moex-budget сам урезает размер до остатка лимитов (открытый риск, дневной запас, просадка).
Читает `trader/orders.json`, `trader/config.json`, `trader/state/broker.json`, `trader/portfolio.json`, `trader/backtest/summary.json`. Пишет вердикт по отпечатку каждой заявки в `trader/state/risk.json` — без PASS на сегодня moex-broker заявку не отправит. Изменили заявку — нужна новая проверка.

Проверка **данных**: дефектные или устаревшие дневные свечи блокируют новую сделку (`max_data_age_days`). Включённая аварийная остановка `trader/HALT` тоже блокирует новые сделки.

Проверка **тренда**: при \`require_trend_alignment: true\` (по умолчанию) покупка блокируется, если неделя и день не смотрят вверх или месяц против; шорт — зеркально. Для позиции без цели вместо «прибыль/риск» проверяется, что издержки не больше 25% риска.

## Правила

- ✗ — блокирующая проверка, ⚠ — предупреждение (сделка разрешена, но скажите о нём пользователю).
- **BLOCK не обходится.** Не редактируйте конфиг, чтобы пропустить конкретную сделку. Лимиты меняет только пользователь, осознанно, и не в моменте после убытка.
- Дневной лимит выбран — сегодня больше не торгуем. Это главная защита от «отыграться».
- Заявки на закрытие позиции (`closing`) снижают риск и проходят всегда.
- Режим рынка: если IMOEX ниже дневной EMA50, свинг-лонги идут против рынка — предложите уменьшить размер.

## Общие правила

- Скрипты лежат в `${CLAUDE_SKILL_DIR}`, общая библиотека — в `${CLAUDE_SKILL_DIR}/../moex-setup/lib`. Состояние пишется в папку `trader/` текущего проекта (или `$TRADER_DIR`).
- Время везде — московское (МСК). `--now "YYYY-MM-DD HH:MM"` разбирает ситуацию на момент в прошлом.
- Бесплатные данные ISS Мосбиржи идут с задержкой около 15 минут. В реальном времени — через токен Т-Инвестиций (настраивается в moex-setup).
- Если скрипт пишет, что нет доступа к iss.moex.com или API Т-Инвестиций, значит у среды нет выхода в интернет к этим сайтам. Если подключён компьютер пользователя (есть инструмент для команд на его компьютере), запустите команду там. Иначе предложите выгрузить свечи в CSV (терминал брокера, экспорт Финама) и передать файл через `--file`. Не придумывайте цифры.
- Это инструмент, а не финансовая рекомендация. Не обещайте прибыль. Большинство людей, торгующих внутри дня, теряют деньги; комиссии — одна из главных причин.
